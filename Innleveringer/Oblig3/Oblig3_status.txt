LÆRT
----
- Valider når BÅDE feltverdi og tabell er i endelig tilstand: visDeltager ->
  reset() -> valider. Validering før reset() vurderer en verdi som forsvinner.
- reset() og element.value = ... utløser IKKE input-hendelsen.
- reset() setter felt tilbake til value-attributtet (eller tomt), men nullstiller
  IKKE setCustomValidity eller title.
- Innebygd validitet (required, min, pattern, type) oppdateres automatisk;
  setCustomValidity og title blir stående til du endrer dem.
- title gir meldingen ved musepeker (Chromium); nettleserens egen melding vises bare
  som boble ved submit.
- else { errormessage = ""; } er nullstillingen. Uten den: setCustomValidity(undefined)
  gir teksten "undefined" og feltet blir alltid ugyldig.
- Et uttrykk alene i en blokk, f.eks. { (x.customError) ... }, er død kode. En betingelse
  må stå i if (...) / else if (...).
- validity-egenskaper: valueMissing, patternMismatch, badInput, rangeUnderflow,
  stepMismatch, customError. customError sier bare noe om ditt eget forrige kall.
- formData.get(...) gir alltid streng; Number(...) for tall.
- insertCell(-1) returnerer cellen. Kjedet .textContent/.innerHTML mister referansen;
  lagre i const først for å bruke den senere.
- innerHTML: aldri med brukerdata (XSS). Fast streng brukes av foreleser selv (slide 67).
- Slide 67 har skrivefeil: "const tabellrekke.innerHTML" (ugyldig) og "celles" (cells).
- insertRow(-1) legger rekka sist; findIndex gir -1 når ingen matcher, så
  insertRow(findIndex(...)) håndterer "større enn alle" uten spesialtilfelle.
- Semikolon skrives alltid ut; ikke stol på automatisk semikoloninnsetting (ASI).
- valueAsNumber for type="time" = millisekunder siden midnatt; NaN når feltet er tomt
  (F11 slide 44). value er "" når feltet er tomt eller halvfylt.
- input-hendelsen på tidsfelt kommer først når hele feltet er fylt ut; deretter for
  hver endring (mellomverdier er normalt).
- Lytter laget inne i en metode husker lokale variabler fra samme kall (closure):
  hver rad får sine egne startElement/sluttElement/lopstidElement.
- Felt som avhenger av hverandre: la begge lytterne kalle SAMME valideringsmetode.
- if-betingelsen beskriver når FEILEN skal vises: «ikke etter» = før eller lik -> <=.
- && krever at alle delene er sanne; én usann del -> else. Kortslutning som i Java.
- Sammenligning med NaN er alltid false. Ikke stol på det; skriv sjekken eksplisitt.
- if / else if / else: else if kjører bare når if var usann, så tidligere grener
  «tar» sine tilfeller først.
- Private metoder kalles alltid med this.#navn(...), også inne i andre metoder.
- Math.trunc kutter desimaler (F12-14 slide 18). % er rest (modulo), som i Java.
- To sifre: if (tall < 10) return `0${tall}`; (padStart finnes, men er ikke i kurset).
- /* ... */ er kommentar; "const x = /* ... */;" er syntaksfeil (mangler verdi).
