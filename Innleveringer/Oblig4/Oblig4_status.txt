Streams og Java (F02-F05)
- [U] Finn én: liste.stream().filter(x -> ...).findFirst().orElse(null)
- [U] Finnes noen: liste.stream().anyMatch(x -> ...)  (alternativ: finnEn(...) != null)
- [U] Sortér: liste.stream().sorted(Comparator.comparing(Klasse::getFelt)).toList()
      sorted() lager ny liste; originalen endres ikke. toList() gir en uforanderlig liste.
- [F] findFirst() returnerer Optional<T> (boks som kan være tom); orElse(x) pakker ut med standardverdi.
- [F] Lambda-parameter (d -> ...) er fritt navn, typen utledes fra strømmen. Kan ikke ha samme
      navn som en eksisterende lokal variabel/parameter.
- [F] a.equals(b) kaster NPE hvis a er null. Sett den verdien du VET ikke er null til venstre:
      d.getMobil().equals(mobil) tåler mobil == null.
- [F] equals() = like/ulike (boolean). compareTo() = rekkefølge (<0, 0, >0).
- [F] static felt = én felles instans for hele appen (delt av alle brukere/tråder).
- [F] || og && kortslutter: i «a == null || a.metode()» kjøres a.metode() aldri når a er null.
      Rekkefølgen i betingelsen er derfor avgjørende for å unngå NPE.

Bean Validation og regex (F18)
- [U] @NotNull(message = ...) + @Pattern(regexp = "...", message = ...) / @Size(min = , max = , message = ...)
- [U] @Pattern og @Size regner null som GYLDIG -> @NotNull må alltid med.
- [U] Controller: @Valid @ModelAttribute("navn") Skjema skjema, BindingResult bindingResult
      (BindingResult rett etter, ellers kastes unntak). bindingResult.hasErrors().
- [F] @Pattern sjekker HELE strengen (Matcher.matches()) -> ^ og $ er unødvendige.
- [F] Regex: [abc] = ett tegn fra klassen. {8} = nøyaktig 8, {1,19} = 1 til 19, * = 0 eller flere.
      Kvantoren gjelder leddet rett foran, nytt tegnvalg for hver gjentakelse.
      [^abc] = ett tegn som IKKE er a, b eller c. a|b = a eller b (hele alternativer).
- [F] | er regex-syntaks og står INNE i strengen: "mann|kvinne". "mann" | "kvinne" er Java-
      operator -> kompileringsfeil. + mellom strenger er Java-sammenslåing før regex-motoren.
- [F] Annoteringsverdier må være kompileringstidskonstanter (static final, + mellom dem er ok).
- [F] Regler som krever oppslag (mobil allerede påmeldt) eller to felt (passord = repetert)
      kan ikke uttrykkes med feltannoteringer -> programmatisk sjekk i controller/hjelpemetode.
- [F] Hjelpemetode som returnerer feilmelding eller null (meldingFraInputValidering) holder
      controller-metoden kort: «String feilmelding = ...; if (feilmelding != null) {...}».

Klientside- vs. tjenersidevalidering
- [F] Klientside (HTML required/pattern, CSS :invalid, JS setCustomValidity): kjører i
      nettleseren FØR innsending. Formål: brukervennlighet. Kan omgås (DevTools, avslått JS,
      curl/Postman). Frivillig i Oblig4.
- [F] Tjenerside (Bean Validation + programmatisk): kjører på tjeneren ETTER mottak. Formål:
      sikkerhet, robusthet, dataintegritet. Kan ikke omgås. Obligatorisk.
      Kan sjekke mot lagrede data (unik mobil). All input behandles som upålitelig.
- [F] Uten tjenervalidering: ugyldige data lagres, krasj (NPE ved manglende felt), sikkerhetshull.
- [F] Hvitelisting (beskriv hva som er LOV) framfor svartelisting (hva som er forbudt).
- [F] Radioknapper/dropdown begrenser bare vanlige brukere; value kan endres i DevTools.
  Modellsvar: «Klientsidevalidering gir rask tilbakemelding, men kan omgås fordi tjeneren ikke
  kontrollerer klienten. Tjenersidevalidering er derfor obligatorisk: all input sjekkes før den
  brukes/lagres, og tjeneren kan i tillegg sjekke mot lagrede data. Bruk hvitelisting.
  I Spring: Bean Validation på skjemaobjekt + @Valid/BindingResult + programmatisk sjekk.»

Sesjoner og innlogging (F19)
- [U] request.getSession(false) = hent eksisterende sesjon, ELLER null hvis ingen. Oppretter ikke.
      Brukes når man bare skal SJEKKE (erInnlogget) eller LOGGE UT.
- [U] request.getSession(true) (= getSession()) = hent eksisterende, ELLER opprett ny.

- [F] Hvorfor HttpServletRequest som parameter, ikke HttpSession: med request kan man velge å
      ikke opprette sesjon (false). En HttpSession-parameter får Spring til å alltid opprette en.
- [F] Attributtnavnet er en vanlig streng; skrivefeil kompilerer, men brukeren blir aldri

- [F] Lagre hele brukerobjektet i sesjonen = enkelt, men kan bli utdatert. Lagre bare id =

      samme feilmelding + redirect tilbake. Null-sjekk FØRST (ellers NPE på getHashetPassord()).

Spring MVC: controllere, URL vs. view, PRG (F16-F19)
- [U] @Controller på klassen. @GetMapping("/x") / @PostMapping("/x") på metoden.
      Returverdi: "viewnavn" (= templates/viewnavn.html) ELLER "redirect:/url" (ny GET-request).
- [F] URL og viewnavn er to forskjellige ting. /innlogging -> view "logginn". Redirect går alltid
      til en URL som har en controller-metode, aldri til et viewnavn eller en .html-fil.
- [F] Samme URL kan ha både GET (vis skjema) og POST (ta imot skjema). Spring velger metode ut
      fra HTTP-metoden. Skjemaets action peker på URL-en, method="post".
- [U] Guard-mønster: sjekk feil/innlogging først, håndter og return tidlig. Deretter happy path.
- [F] Spring injiserer de parameterne metoden ber om (Model, HttpServletRequest,
      RedirectAttributes, @RequestParam, @ModelAttribute). Rekkefølgen er fri, UNNTATT at
      BindingResult må stå rett etter @Valid-parameteren. Man kan legge til parametre i en
      gitt signatur (Model i meldePaa).
- [U] @RequestParam String mobil: navnet må være likt name="mobil" i skjemaet. Mangler
      parameteren -> 400 Bad Request.
- [U] model.addAttribute("navn", verdi) -> ${navn} i malen. Lever bare i denne requesten.
- [U] ra.addFlashAttribute("navn", verdi) + return "redirect:/url" -> ${navn} i malen etter
      redirecten. Brukes for meldinger som skal overleve en redirect (guard, utlogging).
- [F] PRG (Post/Redirect/Get): en POST som ENDRER noe (lagring, innlogging) avsluttes med
      redirect. Nettleseren gjør da en GET, så F5 sender ikke skjemaet på nytt (ingen dobbel
      påmelding).
- [F] Ved valideringsfeil: returner viewet direkte, ingen redirect. Ugyldig POST endrer ingenting,
      så ny innsending er ufarlig. Skjemaobjektet (og BindingResult) finnes bare i samme
      request, så feltene fylles ut igjen uten ekstra kode. (f18a, f20a, Spring-konvensjon.)
      Alternativ: flash + redirect, men da må skjemaobjektet også flashes.
- [F] Flash-attributt etter invalidate() (loggeUt) virker: Spring lagrer det i en ny sesjon
      når redirecten behandles.
- [F] "redirect:x" og "redirect:/x" virker begge når appen ligger på rot. Vær konsekvent.
- [F] Model vs. sesjon: data som trengs på mange sider for innlogget bruker (navn, mobil)
      hentes fra sesjonen. Data for én side (deltagerlisten) legges i modellen.

Thymeleaf (F16-F19, jukselapp)
- [U] th:text="${x}" setter innholdet og ESCAPER (trygt mot XSS). Standardvalg for all data.
- [U] th:utext tolker HTML (ingen escaping). KUN for betrodd innhold, f.eks. konstanten

// PaameldingController - GET viser skjema
@GetMapping("/paamelding")
public String henteSkjema() {
    return "paameldingsskjema";
}

// PaameldingController - POST med validering, guard, PRG
@PostMapping("/paamelding")
public String meldePaa(HttpServletRequest request, Model model,
        @Valid @ModelAttribute("deltager") DeltagerSkjema skjema,
        BindingResult bindingResult) {
    String feilmelding = meldingFraInputValidering(skjema, bindingResult);
    if (feilmelding != null) {
        model.addAttribute("feilmelding", feilmelding);
        return "paameldingsskjema";
    }
    String hashetPassord = PassordService.lagHashetPassord(skjema.getPassord());
    Deltager deltager = skjema.lagDeltager(hashetPassord);
    DeltagerDbService.lagreDeltager(deltager);
    LogginnService.loggInnBruker(request, deltager);
    return "redirect:/paameldt";
}

// Guard for side som krever innlogging (samme mønster i henteDeltagerliste)
@GetMapping("/paameldt")
public String hentePaameldt(HttpServletRequest request, RedirectAttributes ra) {
    if (!LogginnService.erBrukerLoggetInn(request)) {
        ra.addFlashAttribute("feilmelding", Feilmeldinger.KREVER_INNLOGGET_MLD);
        return "redirect:/innlogging";
    }
    return "paameldingsbekreftelse";
}

// DeltagerlisteController - guard + data i modellen
@GetMapping("/deltagerliste")
public String henteDeltagerliste(HttpServletRequest request, Model model, RedirectAttributes ra) {
    if (!LogginnService.erBrukerLoggetInn(request)) {
        ra.addFlashAttribute("feilmelding", Feilmeldinger.KREVER_INNLOGGET_MLD);
        return "redirect:/innlogging";
    }
    model.addAttribute("deltagere", DeltagerDbService.finnAlleSortertPaaFulltNavn());
    return "deltagerliste";
}

// InnUtloggingController - innlogging
@PostMapping("/innlogging")
public String loggeInn(@RequestParam String mobil, @RequestParam String passord,
        HttpServletRequest request, RedirectAttributes ra) {
    Deltager deltager = DeltagerDbService.finnDeltagerMedMobil(mobil);
    if (deltager == null || !PassordService.erPassordKorrekt(passord, deltager.getHashetPassord())) {
        ra.addFlashAttribute("feilmelding", Feilmeldinger.UGYLDIG_BRUKERNAVN_PASSORD_MLD);
        return "redirect:innlogging";
    }
    LogginnService.loggInnBruker(request, deltager);
    return "redirect:deltagerliste";
}

// InnUtloggingController - utlogging
@PostMapping("/utlogging")
public String loggeUt(HttpServletRequest request, RedirectAttributes ra) {
    LogginnService.loggUtBruker(request);
    ra.addFlashAttribute("feilmelding", Feilmeldinger.UTLOGGET_MLD);
    return "redirect:innlogging";
}

// LogginnService
public static boolean erBrukerLoggetInn(HttpServletRequest request) {
    HttpSession session = request.getSession(false);
    return session != null && session.getAttribute("innloggetDeltager") != null;
}
public static void loggUtBruker(HttpServletRequest request) {
    HttpSession session = request.getSession(false);
    if (session != null) {
        session.invalidate();
    }
}
public static void loggInnBruker(HttpServletRequest request, Deltager deltager) {
    loggUtBruker(request);
    HttpSession session = request.getSession(true);
    session.setAttribute("innloggetDeltager", deltager);
    session.setMaxInactiveInterval(120); //sek
}
